# 진본 서비스 플로우 및 운영 정책

## 1. 문서 목적

이 문서는 진본 서비스가 회원, DID, 영상, 블록체인 기록, VC를 어떤 기준으로 다루는지 정리한 정책 문서다.

세부 API나 구현 방법보다 서비스 전체 흐름과 기능 간 책임을 이해하는 것을 목적으로 한다. 구체적인 기술 구현은 각 API 문서와 하위 프로토콜 문서를 따른다.

## 2. 서비스 정의

진본은 원본 영상을 등록하고, 이후 유통되는 영상이 등록 당시의 영상과 일치하는지 확인할 수 있게 하는 서비스다.

진본이 제공하는 증명은 크게 두 가지다.

- **영상 무결성 증명:** 등록 당시의 영상 특징과 현재 영상을 비교하고 블록체인 기록을 확인한다.
- **등록 신뢰성 증명:** 등록 주체와 발급 이력을 DID 및 VC로 확인한다.

영상의 진본 여부는 블록체인 기반 검증을 중심으로 판단한다. VC는 사용자가 보유하고 향후 다른 서비스에 제출할 수 있는 디지털 인증서 역할을 한다.

## 3. 서비스 채널별 역할

| 채널 | 주요 역할 |
|---|---|
| iOS 앱 | 회원가입, 모바일 신분증 로그인, DID/Wallet 관리, 원본 영상 등록, VC 보관 |
| 웹사이트 | 영상 업로드 또는 URL 기반 진본 검증 |
| 크롬 확장 | 웹에서 보고 있는 영상의 빠른 검증 |
| 카카오 챗봇 | 일반 사용자의 간편한 영상 검증 |

앱에도 영상 검증 기능을 제공하지만 핵심 기능은 아니다. 앱의 중심 역할은 **등록자용 Wallet과 원본 영상 관리**다.

## 4. 사용자와 권한

### 일반 회원

- 모바일 신분증으로 본인확인을 완료한 사용자다.
- 자신의 DID와 Wallet을 관리한다.
- 발급받은 VC를 보관하고 확인할 수 있다.

### 공인 등록자

- 진본에서 영상 등록 권한을 부여받은 회원이다.
- 원본 영상을 등록하고 블록체인 기록 및 VC 발급을 요청할 수 있다.
- 영상 등록 권한과 회원의 본인 여부는 서로 별도로 관리한다.

### 비회원 검증자

- 회원가입이나 로그인 없이 영상을 검증할 수 있다.
- 공개 검증 결과만 확인하며 회원의 개인정보나 Wallet 정보에는 접근할 수 없다.

## 5. 회원가입과 로그인 정책

회원가입과 로그인은 분리한다.

### 회원가입

```text
모바일 신분증 본인확인
→ CI 기준 중복 회원 확인
→ PENDING 회원 생성
→ 기기 Wallet 및 DID 생성
→ DID Document 등록
→ 서버 회원과 DID 연결
→ ACTIVE 회원 전환
```

- 회원은 CI를 기준으로 식별한다.
- DID는 회원의 공개 식별자이지만 회원 자체를 판단하는 유일한 기준으로 사용하지 않는다.
- 회원가입은 최초 한 번만 수행한다.
- DID 등록까지 끝나지 않은 회원은 가입 완료 상태로 보지 않는다.

### 로그인

```text
모바일 신분증 본인확인
→ CI 기준 ACTIVE 회원 조회
→ 로그인 토큰 발급
```

- 로그인 과정에서는 새 회원을 자동 생성하지 않는다.
- 미가입 회원은 회원가입을 안내한다.
- 가입 중인 회원은 DID 등록 완료를 안내한다.
- 정지·탈퇴 회원은 로그인할 수 없다.

## 6. DID 및 Wallet 정책

- DID 개인키와 VC 원문은 사용자 Wallet에 저장한다.
- 서버는 개인키를 보관하지 않는다.
- 서버는 회원과 연결된 현재 DID, 등록 시각, 상태 등 운영에 필요한 정보만 관리한다.
- DID는 사용자의 이름이나 CI를 직접 노출하는 수단으로 사용하지 않는다.
- CI와 DID의 연결 정보는 인증과 계정 복구에 필요한 범위에서만 서버 내부에 보관한다.

## 7. 영상 등록 정책

영상 등록은 공인 등록자만 수행할 수 있다.

```text
로그인 및 등록 권한 확인
→ 원본 영상 업로드
→ 정확 해시와 지각 해시 생성
→ 중복 영상 확인
→ Merkle Root 및 전자서명 생성
→ 블록체인 기록
→ 등록 결과 저장
→ Issuer에 Holder 및 영상 클레임 준비
→ 앱 Wallet이 User-Initiated 방식으로 VC 발급 요청
→ Wallet 저장 완료 후 서버에 VC ID 확정
```

- 같은 회원이 동일 파일을 다시 요청하면 신규 블록체인 기록을 만들지 않고 기존 등록 결과를 반환한다.
- 다른 회원이 동일 파일을 등록하려 하면 권리나 등록 권한을 판정하지 않고 등록을 보류한다.
- 최초 등록 사실을 저작권 또는 소유권의 확정 근거로 표현하지 않는다.
- 지각 해시만 유사한 편집본·재인코딩본은 자동 차단하지 않으며 향후 파생본 또는 새 버전 관계로 관리한다.
- 비활성화된 동일 파일도 새 원본으로 중복 등록하지 않고 기존 이력을 기준으로 안내한다.
- 블록체인에는 영상 원문을 저장하지 않고 검증에 필요한 해시와 서명 정보만 기록한다.
- 영상 원문 보관 여부는 별도의 스토리지 정책으로 관리하며 블록체인 기록과 구분한다.
- 영상 등록 당시의 DID와 블록체인 트랜잭션은 역사적 기록이므로 이후 DID가 변경되어도 수정하지 않는다.
- 회원의 영상 소유권은 현재 DID가 아니라 내부 회원 ID를 기준으로 유지한다.
- 서버가 Wallet을 대신하여 VC 발급을 완료하거나 발급 결과를 임의로 폴링하지 않는다.
- 영상 등록 성공과 VC 발급 성공은 분리하며, 발급 실패 시 영상은 유지하고 Wallet에서 재시도할 수 있다.

## 8. 영상 검증 정책

영상 검증은 로그인 없이 제공하는 공개 기능을 원칙으로 한다.

```text
검증할 영상 또는 URL 입력
→ 정확 해시 비교
→ 필요 시 지각 해시 유사도 비교
→ 블록체인 기록과 무결성 확인
→ VC 상태 및 발급 신뢰성 확인
→ 종합 검증 결과 제공
```

검증 결과는 다음 의미를 구분해 제공한다.

- **진본:** 등록된 영상과 일치하며 블록체인 기록이 유효하다.
- **유사 영상:** 재인코딩 등으로 파일은 달라졌지만 등록 영상과 높은 유사성이 있다.
- **변조 의심:** 등록 기록은 있으나 현재 영상의 특징이 기준을 벗어난다.
- **등록되지 않음:** 진본 데이터에서 일치하는 기록을 찾지 못했다.
- **비활성:** 등록자가 해당 영상의 사용 상태를 비활성화했다.
- **확인 불가:** 외부 시스템 또는 네트워크 문제로 최종 판단을 내릴 수 없다.

`확인 불가`를 `위조`나 `등록되지 않음`으로 처리하지 않는다. 블록체인 검증과 VC 검증 결과도 화면에서 구분해 표현한다.

## 9. VC 정책

- VC는 영상 진본 등록 사실을 사용자가 보유하고 제출할 수 있게 하는 디지털 인증서다.
- VC는 블록체인 검증을 대체하지 않고 보완한다.
- VC 원문은 앱 Wallet에 저장하고 서버는 `vcId`, 대상 영상, 발급 및 폐기 상태를 관리한다.
- VC에는 대상 영상을 식별할 수 있는 정보와 기존 블록체인 기록을 연결할 수 있는 정보가 포함되어야 한다.
- VC가 없거나 발급에 실패하더라도 블록체인 등록이 성공했다면 영상 진본 기록은 유지한다. 단, 사용자에게 VC 발급 상태를 명확히 표시한다.
- 폐기되거나 만료된 VC는 유효한 인증서로 표시하지 않는다.

## 10. 앱 재설치 및 기기 변경 정책

앱 삭제는 서버 회원 탈퇴를 의미하지 않는다.

```text
모바일 신분증으로 기존 회원 로그인
→ 로컬 DID 존재 여부 확인
→ DID가 없으면 새 DID 생성
→ 1회용 재연결 권한으로 서버 DID 교체
→ 기존 영상 소유권 복원
→ 사용자가 선택한 영상의 VC 재발급
```

- 기존 회원이 재설치 후 다시 회원가입하는 것은 허용하지 않는다.
- DID 재연결은 모바일 신분증 재인증 직후에만 허용한다.
- 재연결 권한은 짧은 시간 동안 한 번만 사용할 수 있다.
- 새 DID 연결 전후의 이력은 감사 목적으로 남긴다.
- 과거 영상의 블록체인 DID 기록은 유지하고 회원 소유권만 복원한다.
- 기존 VC는 새 VC가 Wallet에 저장되고 검증된 이후에 폐기한다.

VC 재발급의 상세 상태 및 실패 처리 기준은 [VC 재발급 프로토콜](vc-reissuance-protocol.md)을 따른다.

## 11. 영상 및 VC 비활성화 정책

- 등록자는 자신이 등록한 영상만 비활성화할 수 있다.
- 비활성화는 기존 블록체인 기록을 삭제하는 행위가 아니다.
- 비활성화 사실을 별도 기록으로 남기고 이후 검증 결과에 반영한다.
- 영상에 연결된 VC도 정책에 따라 폐기 상태로 전환한다.
- 운영상 복구가 필요한 경우 관리자 임의 수정이 아니라 별도의 복구 이력으로 처리한다.

## 12. 개인정보 및 보안 정책

- 모바일 신분증 인증 결과에서 서비스에 필요한 최소 정보만 사용한다.
- CI는 회원 중복 확인과 계정 복구를 위한 내부 식별값으로만 사용한다.
- CI, DID, 회원 ID의 연결 관계는 외부 검증 응답에 노출하지 않는다.
- 액세스 토큰과 리프레시 토큰은 역할과 수명을 구분한다.
- DID 재연결, VC 재발급과 같이 소유권에 영향을 주는 작업은 일반 로그인보다 강화된 단기 권한을 사용한다.
- 동일 인증 세션에 대한 중복 요청을 차단하고 성공·실패·취소·만료 시 폴링을 종료한다.
- 외부 DID, 블록체인, 모바일 신분증 시스템의 일시적 장애는 재시도 가능한 상태와 최종 실패 상태를 구분한다.

## 13. 데이터 정합성 원칙

- 회원의 기준 식별자는 내부 회원 ID이며 CI는 본인확인 연결 정보로 사용한다.
- DID 변경으로 기존 영상 소유권이 사라지지 않아야 한다.
- 블록체인에 기록된 과거 데이터는 수정하지 않는다.
- VC 교체는 기존 ID를 덮어쓰기 전에 발급·검증·폐기 이력을 별도로 남긴다.
- 외부 시스템 호출과 DB 저장이 일부만 성공한 경우를 대비해 작업 상태와 재시도 기준을 관리한다.
- 동일 요청이 반복되어도 영상, VC, 회원 상태가 중복 생성되지 않도록 멱등성을 보장한다.

## 14. 서비스 상태 기준

### 회원 상태

| 상태 | 의미 |
|---|---|
| `PENDING` | 본인확인은 완료했지만 DID 등록이 끝나지 않음 |
| `ACTIVE` | 가입과 DID 연결이 완료되어 정상 이용 가능 |
| `SUSPENDED` | 운영 정책에 의해 이용 정지 |
| `WITHDRAWN` | 탈퇴 처리됨 |

### 영상 상태

| 상태 | 의미 |
|---|---|
| 등록 처리 중 | 해시, 블록체인 또는 VC 처리가 진행 중 |
| 활성 | 등록과 블록체인 기록이 유효함 |
| VC 발급 대기 | 영상 등록은 유효하지만 VC 발급이 완료되지 않음 |
| 비활성 | 등록자가 사용 상태를 비활성화함 |
| 처리 실패 | 필수 등록 과정이 완료되지 않음 |

## 15. 정책 우선순위

진본의 기능을 설계하거나 변경할 때 다음 순서를 우선한다.

1. 원본 영상과 블록체인 기록의 무결성
2. 회원 및 영상 소유권의 안전한 유지
3. Wallet 개인키와 개인정보의 비노출
4. VC 발급·보관·폐기 이력의 정합성
5. 여러 채널에서 일관된 검증 결과 제공
6. 실패 시 사용자가 안전하게 재시도할 수 있는 경험
